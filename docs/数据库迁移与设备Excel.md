# 数据库迁移与设备 Excel

## 数据库版本

八张核心业务表保持原有名称；新增独立 `operation_log` 审计表，共九张业务表，另有 Flyway 的 `flyway_schema_history`。

| 版本 | 内容 |
| --- | --- |
| V1 | 八张核心业务表初始结构，不插入固定密码 |
| V2 | 按需补充账号邮箱验证、手机验证、授权版本列；不重置密码或绑定信息 |
| V3 | 新增操作审计表与查询索引 |

原启动期 AccountSchemaMigrator DDL 已由 Flyway 接管。不要修改已经执行的迁移文件；后续变更新建 V4、V5 等版本。MySQL DDL 并非完整事务，升级失败时应先核对实际结构和历史记录，不能直接删除历史或反复执行建表脚本。

### 空库

配置正确连接并启动后端，Flyway 依次执行 V1—V3。此路径只创建结构，不创建管理员。Docker 的首次数据卷初始化先执行 `deploy/mysql` 的八表结构与初始账号脚本，随后通过下述已知结构接管路径升级。

### 已有八表库

1. 先备份数据库和上传文件，并确认可恢复；建议先在备份副本演练。
2. 确认目标库是本项目既有库，只有八张已知业务表，且关键列与当前代码对应。自动预检仅检查表名与关键列，不代表全量索引、约束、数据类型或业务数据审查。
3. 对无 Flyway 历史的本机旧库，显式设置环境变量 `SCHEMA_ADOPT_EXISTING=true` 再启动。默认本机配置为 false，无许可会拒绝接管。
4. 只有开关开启且预检通过才建立 V1 基线，然后执行 V2、V3。不会重新执行 V1、清空数据、覆盖账号或预约工单。
5. 验证迁移历史、启动日志与业务流程后，关闭接管开关；已有历史的库会正常校验并升级。

根 Compose 的 `SCHEMA_ADOPT_EXISTING` 默认 true，是为了兼容其先建八表的初始化脚本；它同样受到结构预检保护。直接使用旧数据卷前仍须备份和核对；不确定的结构应显式设为 false，禁止盲目基线。不要设置 `baseline-on-migrate=true` 绕过该策略，也不要使用 Flyway clean 或 `docker compose down -v` 更新系统。

## 设备表格接口

均要求有效 admin 或 lab_admin 会话（`Authorization: Bearer <token>`）。lab_admin 只能处理本人负责实验室的设备。

| 方法与路径 | 返回 |
| --- | --- |
| GET `/equipment/import-template` | 无示例设备的空 XLSX 模板 |
| GET `/equipment/export` | 当前条件、当前管理范围内 XLSX，最多2000条 |
| POST `/equipment/import` | multipart 字段 `file`；成功返回 `Result.data.importedCount` |

导出支持 `labId`、`name`、`model`、`equipmentCode`、`status`，分页参数不限制导出行数。超过2000条需缩小条件，不能悄悄截断。网页入口位于管理员的设备管理页。

模板列顺序：设备编号、设备名称、实验室ID、型号、制造商、采购日期、设备说明。采购日期使用 `yyyy-MM-dd` 或 Excel 日期单元格。设备编号建议用文本格式保留前导零。

导入要求：

- 仅 `.xlsx`，压缩文件最大2 MiB、单工作表、最多500条数据。
- 限制 ZIP 条目数、单条目与累计解压体积；拒绝公式、宏/嵌入附件及错误单元格。
- 全量验证必填项、实验室管理范围、编号重复；已逻辑删除设备占用的编号也不能复用。
- 只新增、全部状态设为“可用”。不通过表格覆盖现有设备或改变预约/维修状态。
- 任一行失败整批回滚；成功提交后失效设备列表缓存。
- 单实例最多同时处理一个导入或导出任务，忙时返回429；不是分布式业务锁。多实例的唯一性由事务、行锁和数据库唯一索引共同保证。

## 审计与追踪

admin 在 `/operation-logs` 查看审计，接口 `GET /operation-log/page` 支持 current、size（最多100）、module、success（0/1）。模块值为 user、lab、equipment、reservation、repair。

管理写操作包含操作人、模块、动作、路径、数值主键、耗时、结果码、traceId 等元数据。审计使用独立事务，写入失败不会覆盖原业务结果；因此数据库不可用时可能缺少记录。注解只记录进入业务方法的操作，鉴权和参数校验提前拒绝的请求不会全部进入此表，不能把它当作完整安全访问日志。

IP 当前保存直连地址，不盲目信任转发头；经过 Nginx 后可能是代理地址。需要原始客户端 IP 时应另行配置受信代理链。暂未提供审计自动归档，需结合实际增长量制定保留期限。

## 演示与并发说明

首次 Docker 初始化已使用真实类别名称的实验室、设备，没有插入远期预约。测试中的2099年边界数据不应批量改成生产数据。演示时使用独立数据库、学生测试账号和当天之后的有效时段，按“申请→审核→签到”和“报修→受理→维修→完成”真实操作，不向已有业务库注入假记录。

本轮保留固定常量 `FOR UPDATE` 与“先读取实验室归属、再按实验室→设备顺序加锁”的必要逻辑；常量锁子句不构成字符串注入。删除前置归属读取或改反锁顺序可能破坏并发约束，未按评审建议机械改动。
